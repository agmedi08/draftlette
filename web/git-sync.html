Guide

Set up Git sync

Keep the texts on your Draftling backed up and in sync with a private Git repository.

How it works

Draftling has a built-in Git client. Press Ctrl+W to connect to Wi-Fi, then Ctrl+G, and Draftling commits your edits, pulls in anything new from the server, merges the two, and pushes the result back, using the same standard HTTPS protocol that desktop git uses. A full commit history is kept in .git/ on the SD card, so you can also plug the card into a computer and work with it there.

This works with any standard Git host. Below are step-by-step instructions for the three most common ones. You only need to do this once per device.

Draftbox

With Draftbox you skip all of this: create a repository there, get a one-time password, and enter it in the Draftling F1 menu ("Connect a Draftbox repository"). The device writes git.cfg for you.

Before you start

  1. Create an empty private repository on your Git host (no README, no .gitignore, no licence; a completely empty repository is simplest). Note its branch name; new repositories usually default to main.
  2. Make sure your Draftling can reach the Internet: use the Wi-Fi connection dialog in the F1 menu, or put a wifi.cfg file on the SD card root with your network name on the first line and the password on the second line.

Everything below ends with a small text file called git.cfg on the SD card root. Create it with any text editor. Keep it private: it contains an access token.

GitHub

  1. Open Settings → Developer settings → Personal access tokens → Fine-grained tokens and click Generate new token.
  2. Give it a name (e.g. draftling) and an expiry date.
  3. Under Repository access choose Only select repositories and pick your repository.
  4. Under Permissions → Repository permissions set Contents to Read and write. (This also switches Metadata to read-only automatically, which is fine.)
  5. Click Generate token and copy the value. It starts with github_pat_ and is shown only once.

git.cfg:

repo_url=https://github.com/YOUR-USER/YOUR-REPO
branch=main
token=github_pat_xxxxxxxxxxxxxxxxxxxx
author_name=Jane Doe
author_email=jane@example.com

GitLab

  1. Open your project and go to Settings → Access tokens.
  2. Click Add new token. Give it a name and an expiry date.
  3. Set the Role to Developer (or higher).
  4. Tick the read_repository and write_repository scopes.
  5. Click Create project access token and copy the value. It starts with glpat- and is shown only once. Note the token's name too; you need it as the username.

git.cfg:

repo_url=https://gitlab.com/YOUR-USER/YOUR-REPO
branch=main
username=draftling-token-name
token=glpat-xxxxxxxxxxxxxxxxxxxx
author_name=Jane Doe
author_email=jane@example.com

If you use a personal access token (User Settings → Access Tokens) instead of a project token, set username to your GitLab account username.

Codeberg

  1. Open Settings → Applications.
  2. Under Manage Access Tokens enter a token name (e.g. draftling).
  3. Expand Select permissions and set repository to Read and Write.
  4. Click Generate Token and copy the value. It is shown only once.

git.cfg:

repo_url=https://codeberg.org/YOUR-USER/YOUR-REPO
branch=main
username=YOUR-CODEBERG-USERNAME
token=xxxxxxxxxxxxxxxxxxxx
author_name=Jane Doe
author_email=jane@example.com

The same steps work for any Gitea or Forgejo host, not just Codeberg.

First sync

  1. Put git.cfg on the SD card root and insert the card.
  2. Power on Draftling and connect Wi-Fi: press Ctrl+W, or use the F1 menu.
  3. Press Ctrl+G to sync.

On the very first sync Draftling downloads the repository's history (nothing, for an empty repository), commits your current files, and pushes them up. After that, every Ctrl+G is a quick two-way merge.

If both sides changed the same lines of a file, Draftling writes both versions into the file with <<<<<<< / ======= / >>>>>>> markers and still commits, so nothing is ever lost. Edit the file to resolve it and sync again.

Full details of the protocol, the on-card layout and the merge behaviour are in docs/git-sync.md.

Troubleshooting

  • Auth failed / 401: wrong token, wrong username, or the token lacks write access to Contents / repository.
  • Nothing happens / no Wi-Fi: check the Wi-Fi settings (in wifi.cfg: network name on line 1, password on line 2, no extra spaces) and that you connected with Ctrl+W first.
  • 404: check repo_url; the repository must already exist.
  • Push rejected: the server's copy changed while syncing. Just press Ctrl+G again.
  • Only some files sync: that is by design. Only .md, .fountain and .txt files in the top folder of the card are synchronized; sub-directories, images and other file types are not.
